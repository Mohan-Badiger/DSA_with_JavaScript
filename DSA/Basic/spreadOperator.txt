1. WHAT IS THE SPREAD OPERATOR?
================================================================================

EASY DEFINITION:
The Spread Operator is written with three dots: `...`
It takes an iterable (like an Array, String, Set, or Object) and "unpacks" or 
"spreads" its individual elements out into a new place.

REAL-WORLD ANALOGY:
Imagine a packed suitcase:
- The Array is the closed suitcase.
- The Spread Operator (`...`) opens the suitcase and takes every item out individually, 
  laying them out on the bed so you can repack them into a new suitcase or mix them with new clothes.

Visual Representation:
[ 1, 2, 3 ]   ===>  ...  ===>   1, 2, 3   (unpacked into loose items)

================================================================================
2. SPREAD OPERATOR (...) vs. REST PARAMETER (...)  [#1 INTERVIEW QUESTION]
================================================================================

Both use the exact same three dots `...`, but they do OPPOSITE things!

- SPREAD: UNPACKS / EXPANDS values into individual elements.
  (Used in array literals, function calls, object literals)
  Example: Math.max(...[1, 5, 2])  -> Math.max(1, 5, 2)

- REST: GATHERS / CONDENSES multiple individual elements into a single array.
  (Used in function parameter lists and destructuring)
  Example: function sum(...numbers) { ... }

Quick Comparison Table:
--------------------------------------------------------------------------------
Operator | What it Does        | Where it Appears              | Example
---------|---------------------|-------------------------------|-----------------
SPREAD   | Unpacks an array    | Function call / Array literal | [...arr1, ...arr2]
REST     | Packs into an array | Function parameter list       | function(a, ...rest)
REST     | Gathers remainder   | Left side of destructuring    | const [first, ...others] = arr
--------------------------------------------------------------------------------

Code Example:
--------------------------------------------------
// REST gathers inputs into an array
function collectAll(...items) { // <-- REST (packs arguments into array)
    console.log(items);
}
collectAll(1, 2, 3); // Output: [1, 2, 3]

// SPREAD unpacks array into separate items
const nums = [10, 20, 30];
console.log(...nums); // <-- SPREAD (Output: 10 20 30)
--------------------------------------------------

3. CORE EVERYDAY USE CASES
================================================================================

--------------------------------------------------
1. COPYING ARRAYS (Shallow Copy)
--------------------------------------------------
In JavaScript, arrays are reference types. Assigning `b = a` does NOT copy the array;
both variables point to the same array in memory. Spread creates a new array!

const original = [1, 2, 3];
const badCopy = original;       // Points to the SAME array in memory!
const goodCopy = [...original]; // Creates a brand-new array!

goodCopy.push(99);
console.log(original); // [1, 2, 3] (Untouched! Safe!)
console.log(goodCopy); // [1, 2, 3, 99]


--------------------------------------------------
2. MERGING & COMBINING ARRAYS
--------------------------------------------------
Easily combine multiple arrays without `.concat()`:

const fruits = ["apple", "banana"];
const veggies = ["carrot", "spinach"];

const food = [...fruits, ...veggies];
console.log(food); // ["apple", "banana", "carrot", "spinach"]


--------------------------------------------------
3. ADDING ELEMENTS ANYWHERE
--------------------------------------------------
Insert elements at the beginning, middle, or end:

const base = [2, 3];
const full = [1, ...base, 4, 5];
console.log(full); // [1, 2, 3, 4, 5]


--------------------------------------------------
4. PASSING ARRAYS TO FUNCTIONS EXPECTING SEPARATE ARGUMENTS
--------------------------------------------------
Functions like `Math.max()` or `Math.min()` expect separate numbers, NOT an array:

const scores = [45, 82, 99, 23];

// Bad:
Math.max(scores);      // NaN (because Math.max([45, 82...]) fails)

// Good with Spread:
Math.max(...scores);   // 99 (Same as Math.max(45, 82, 99, 23))


--------------------------------------------------
5. CONVERTING STRINGS & ITERABLES TO ARRAYS
--------------------------------------------------
A. Convert String to Char Array:
   const str = "hello";
   const chars = [...str]; // ['h', 'e', 'l', 'l', 'o']

B. Remove Duplicates using Set + Spread (Super common in DSA!):
   const arrWithDuplicates = [1, 2, 2, 3, 4, 4, 5];
   const uniqueArr = [...new Set(arrWithDuplicates)];
   console.log(uniqueArr); // [1, 2, 3, 4, 5]


--------------------------------------------------
6. OBJECT CLONING & MERGING (PROPERTY OVERRIDING)
--------------------------------------------------
Spread unpacks object keys and values into a new object:

const user = { name: "John", age: 25 };
const updatedUser = { ...user, age: 26, city: "New York" };

console.log(updatedUser); 
// { name: "John", age: 26, city: "New York" }
// Note: 'age' was overridden because it came AFTER '...user'.

4. CRITICAL DSA KNOWLEDGE & GOTCHAS (MUST KNOW FOR INTERVIEWS)
================================================================================

--------------------------------------------------------------------------------
GOTCHA 1: HIDDEN TIME & SPACE COMPLEXITY TRAP (LEADS TO TLE ON LEETCODE!)
--------------------------------------------------------------------------------
Spreading an array `[...arr]` is NOT free!
It loops through all elements behind the scenes.

- Time Complexity of `[...arr]`: O(N)
- Space Complexity of `[...arr]`: O(N)

DANGER IN LOOPS:
If you do spread inside a loop of size N:
--------------------------------------------------
// BAD DSA CODE (Accidental O(N^2) Time Complexity!):
let result = [];
for (let i = 0; i < n; i++) {
    result = [...result, i]; // O(result.length) on every step!
    // Total Time: 1 + 2 + 3 + ... + N = O(N^2) -> TLE!
}

// OPTIMAL DSA CODE (O(N) Time Complexity):
let result = [];
for (let i = 0; i < n; i++) {
    result.push(i); // O(1) amortized time!
    // Total Time: O(N) -> PASSES!
}
--------------------------------------------------


--------------------------------------------------------------------------------
GOTCHA 2: THE BACKTRACKING / RECURSION TRAP (Pass-by-Reference Bug)
--------------------------------------------------------------------------------
In problems like Subsets, Permutations, Combination Sum:
Because arrays in JavaScript are passed by reference, pushing `path` pushes the
SAME reference that gets modified later when backtracking!

--------------------------------------------------
// Subsets / Permutations example:
function subsets(nums) {
    const result = [];
    
    function backtrack(start, currentPath) {
        // TRAP ALERT:
        // result.push(currentPath); // BUG! Pushes reference. At the end, all items become []!
        
        // CORRECT: Make a shallow copy with spread operator!
        result.push([...currentPath]); 
        
        for (let i = start; i < nums.length; i++) {
            currentPath.push(nums[i]);
            backtrack(i + 1, currentPath);
            currentPath.pop(); // Backtrack
        }
    }
    
    backtrack(0, []);
    return result;
}
--------------------------------------------------
Why it matters:
When backtracking modifies `currentPath.pop()`, without `[...currentPath]`, 
the saved result in `result` will also get emptied!


--------------------------------------------------------------------------------
GOTCHA 3: `Math.max(...arr)` CALL STACK CRASH ON LARGE INPUTS
--------------------------------------------------------------------------------
In JavaScript, function arguments are pushed onto the execution stack.
The engine has an argument limit (typically ~65,536 elements).

If an array has 100,000 elements in LeetCode:
--------------------------------------------------
const largeArr = new Array(100000).fill(1);

// CRASH! 
// RangeError: Maximum call stack size exceeded (or Too many arguments)
Math.max(...largeArr); 

// SAFE DSA ALTERNATIVE (O(N) Time, O(1) Space):
let maxVal = -Infinity;
for (let i = 0; i < largeArr.length; i++) {
    if (largeArr[i] > maxVal) maxVal = largeArr[i];
}
// Or:
const maxValSafe = largeArr.reduce((max, val) => val > max ? val : max, -Infinity);
--------------------------------------------------


--------------------------------------------------------------------------------
GOTCHA 4: SHALLOW COPY vs DEEP COPY TRAP
--------------------------------------------------------------------------------
Spread only copies the FIRST level.
If the array or object contains nested arrays or objects, their references are copied,
NOT the values!

Example:
--------------------------------------------------
const matrix = [ [1, 2], [3, 4] ];
const copyMatrix = [...matrix];

// Changing top-level element doesn't affect original:
copyMatrix.push([5, 6]);
console.log(matrix.length); // 2 (Original is unchanged)

// BUT modifying a nested item DOES affect original!
copyMatrix[0][0] = 999;
console.log(matrix[0][0]); // 999! (MUTATED! Shared nested reference!)
--------------------------------------------------

How to do a true Deep Copy in modern JavaScript:
const deepCopy = structuredClone(matrix); // Built-in modern JS method

5. INTERVIEW QUESTIONS & EDGE CASES
================================================================================

Q1: What happens if you spread non-iterables like null, undefined, or numbers in an Array?
    console.log([...null]);      // TypeError: null is not iterable
    console.log([...undefined]); // TypeError: undefined is not iterable
    console.log([...123]);       // TypeError: 123 is not iterable

Q2: What happens if you spread null, undefined, or numbers in an Object?
    // In objects, it does NOT throw an error! It silently ignores them:
    const obj = { ...null, ...undefined, ...123 };
    console.log(obj); // Output: {} (Empty object!)

Q3: Does the order of spreading matter in Objects?
    YES! Later properties overwrite earlier ones with the same key.
    const a = { x: 1, y: 2 };
    console.log({ ...a, x: 10 }); // { x: 10, y: 2 }  (x is 10)
    console.log({ x: 10, ...a }); // { x: 1, y: 2 }   (x is overwritten back to 1)

Q4: What is the difference between Array.slice() and Spread?
    Both perform a shallow copy with O(N) time & space.
    - `arr.slice()` is slightly faster in micro-benchmarks.
    - `[...arr]` is cleaner, modern, and works on ANY iterable (Sets, Maps, Strings, NodeLists),
      whereas `.slice()` only works on Arrays.

6. QUICK REVISION CHEAT SHEET
================================================================================

1. WHAT IT DOES:
   - Expands an iterable into individual elements (`...iterable`).

2. SPREAD vs REST:
   - Spread: unpacks values (`Math.max(...nums)`, `[...a, ...b]`).
   - Rest: gathers values into an array (`function foo(...args)`).

3. TOP DSA PATTERNS:
   - Deduplication: `[...new Set(arr)]` -> O(N) time & O(N) space.
   - String to Array: `[...str]` -> splits by characters (handles Unicode properly).
   - Backtracking snapshot: `result.push([...current])` -> prevents reference mutation.

4. 3 BIGGEST TRAPS TO AVOID IN DSA:
   - Avoid spreading inside a loop: turns O(N) into O(N^2). Use `.push()`.
   - Avoid `Math.max(...arr)` on huge arrays (> 65,000 items). Use standard loop.
   - Remember it is a SHALLOW copy; nested objects/arrays are still shared by reference!
