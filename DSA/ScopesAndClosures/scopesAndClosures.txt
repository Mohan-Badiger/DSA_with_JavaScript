1. WHAT IS SCOPE?
================================================================================

EASY DEFINITION:
Scope is the boundary or area in your code where a variable is accessible and 
can be used. If a variable is outside that boundary, you cannot access it.

REAL-WORLD ANALOGY:
Think of Scope like ID cards / security badges:
- Global Scope = A city park: anyone in the city can enter.
- Function Scope = An office building: only employees who entered that building can access the cafeteria inside.
- Block Scope = A private locked office cabin inside that building: only the person with that room's key can see what is inside.

--------------------------------------------------------------------------------
2. TYPES OF SCOPES IN JAVASCRIPT
--------------------------------------------------------------------------------

JavaScript has 4 main types of scope:

1. GLOBAL SCOPE:
   - Any variable declared outside of all functions or blocks belongs to the Global Scope.
   - It can be accessed and modified from ANYWHERE in your program.

   Example:
   --------------------------------------------------
   let globalName = "Alice"; // Global variable

   function sayHello() {
       console.log("Hello, " + globalName); // Accessible here!
   }

   sayHello(); // Output: Hello, Alice
   console.log(globalName); // Output: Alice
   --------------------------------------------------
   Warning: Avoid creating too many global variables because any part of your code
   can accidentally overwrite them, causing bugs (known as "namespace pollution").


2. FUNCTION (LOCAL) SCOPE:
   - Variables created inside a function are "local" to that function.
   - They cannot be seen or accessed from outside the function.
   - They are created when the function runs, and destroyed when it finishes.

   Example:
   --------------------------------------------------
   function greet() {
       let localSecret = "12345";
       console.log(localSecret); // Works fine here
   }

   greet(); // Output: 12345
   console.log(localSecret); 
   // ReferenceError: localSecret is not defined (Cannot access from outside!)
   --------------------------------------------------


3. BLOCK SCOPE (Introduced in ES6):
   - A block is any code enclosed within curly braces `{ ... }` (e.g., in `if`, `for`, `while`).
   - Variables declared with `let` and `const` ARE block-scoped.
   - Variables declared with `var` ARE NOT block-scoped (they leak out to function/global scope!).

   Example with let / const:
   --------------------------------------------------
   {
       let insideBlock = "I am safe inside!";
       const blockConst = 100;
       console.log(insideBlock); // Output: I am safe inside!
   }
   console.log(insideBlock); // ReferenceError: insideBlock is not defined
   --------------------------------------------------

   Example with var (Notice how it leaks!):
   --------------------------------------------------
   if (true) {
       var leaked = "I leaked out!";
   }
   console.log(leaked); // Output: "I leaked out!" (var ignores block scope!)
   --------------------------------------------------


4. MODULE SCOPE:
   - When using ES Modules (`<script type="module">` or files with `import`/`export`),
     each file has its own module scope.
   - Variables declared at top level of a module are NOT attached to the global `window` object.
   - Other files can only access items that you explicitly `export`.

3. LEXICAL SCOPE & THE SCOPE CHAIN
================================================================================

EASY DEFINITION:
- "Lexical" means "where it is written in the physical code".
- Lexical Scope means an inner function has access to variables declared in its 
  outer (parent) scope simply because of where the function was physically defined.

THE SCOPE CHAIN:
When JavaScript looks for a variable:
1. It first searches in the **current local scope**.
2. If not found, it moves up to the **immediate parent scope**.
3. It keeps moving up, level by level, through the chain.
4. Finally, it reaches the **Global Scope**.
5. If still not found, it throws a `ReferenceError`.

IMPORTANT RULE:
- Inner scopes can look OUTWARD and upward.
- Outer scopes CANNOT look inward.

Visual Diagram:
+-----------------------------------------------------------+
| Global Scope (name = "Peter")                             |
|   +-----------------------------------------------------+  |
|   | Outer Function Scope (age = 30)                     |  |
|   |   +-----------------------------------------------+ |  |
|   |   | Inner Function Scope (city = "Tokyo")          | |  |
|   |   | -> Can see: city, age, name                   | |  |
|   |   +-----------------------------------------------+ |  |
|   |   -> Can see: age, name (Cannot see city!)          |  |
|   +-----------------------------------------------------+  |
|   -> Can see: name (Cannot see age or city!)              |
+-----------------------------------------------------------+

Code Example:
--------------------------------------------------
let globalVal = "I am Global";

function outerFunction() {
    let outerVal = "I am Outer";

    function innerFunction() {
        let innerVal = "I am Inner";

        console.log(innerVal);  // "I am Inner" (from local)
        console.log(outerVal);  // "I am Outer" (found in parent scope)
        console.log(globalVal); // "I am Global" (found in global scope)
    }

    innerFunction();
    // console.log(innerVal); // ERROR: outerFunction cannot look inside innerFunction!
}

outerFunction();
--------------------------------------------------

4. HOISTING & THE TEMPORAL DEAD ZONE (TDZ)
================================================================================

WHAT IS HOISTING?
During the compilation/creation phase, JavaScript sets aside memory for variable
and function declarations before executing the code line-by-line.

1. `var` is hoisted and initialized with `undefined`:
   console.log(a); // Output: undefined (no crash, but value not ready)
   var a = 10;
   console.log(a); // Output: 10

2. `let` and `const` are hoisted, but NOT initialized:
   The time between entering the scope and the actual line where the variable is declared 
   is called the TEMPORAL DEAD ZONE (TDZ).
   Accessing them in the TDZ causes a `ReferenceError`.

   console.log(b); // ReferenceError: Cannot access 'b' before initialization
   let b = 20;

3. Function Declarations are hoisted completely with their definitions:
   sayHi(); // Output: "Hi!" (Works because entire function is hoisted)
   function sayHi() {
       console.log("Hi!");
   }

================================================================================
5. COMPARISON TABLE: VAR vs LET vs CONST
================================================================================

Feature         | var                      | let                 | const
----------------|--------------------------|---------------------|---------------------
Scope           | Function scope           | Block scope `{}`    | Block scope `{}`
Hoisting        | Hoisted to `undefined`   | Hoisted (in TDZ)    | Hoisted (in TDZ)
Re-declaration  | Allowed in same scope    | Error               | Error
Re-assignment   | Allowed                  | Allowed             | Error (Immutable ref)
Global Window   | Adds property to window  | Does not attach     | Does not attach

RULE OF THUMB:
Always use `const` by default. Use `let` only when you know the value will change. 
Avoid `var` in modern JavaScript.

6. WHAT IS A CLOSURE?
================================================================================

EASY DEFINITION:
A Closure is a function that "remembers" and continues to access variables from 
its outer (lexical) scope, even after the outer function has finished executing 
and returned!

Normally, when a function finishes executing, all of its local variables are destroyed 
(garbage collected). But if an inner function still references those variables, 
JavaScript keeps those variables alive in memory. That combination is a CLOSURE.

REAL-WORLD ANALOGY:
Imagine a student moving out of their parents' house into a college dorm.
Before leaving, they pack a **Backpack** with family photos and home keys.
Even though the parents' house is far away and the visit is over, the student 
still has everything they packed in their backpack wherever they go.
- Outer Function = Parents' house
- Local variables = Items in the house
- Inner Function = The student
- Closure = The backpack containing remembered variables

--------------------------------------------------------------------------------
7. HOW CLOSURES WORK (STEP-BY-STEP BREAKDOWN)
--------------------------------------------------------------------------------

Code Example:
--------------------------------------------------
function createGreeter(greeting) {
    // Outer function's local variable: 'greeting'

    return function(name) {
        // Inner function
        console.log(greeting + ", " + name + "!");
    };
}

// Step 1: Call createGreeter
const sayHello = createGreeter("Hello");
const sayGoodbye = createGreeter("Goodbye");

// At this point, createGreeter() has finished executing and exited the call stack!
// Normally, 'greeting' should be destroyed. BUT:

// Step 2: Call the returned inner functions
sayHello("Alice");   // Output: "Hello, Alice!"
sayHello("Bob");     // Output: "Hello, Bob!"
sayGoodbye("Charlie"); // Output: "Goodbye, Charlie!"
--------------------------------------------------

EXPLANATION STEP-BY-STEP:
1. When `createGreeter("Hello")` is called:
   - A new execution context is created with `greeting = "Hello"`.
   - It returns the inner anonymous function.
   - `createGreeter` finishes and is popped off the Call Stack.
2. The inner function maintains a hidden reference (`[[Environment]]`) to the scope where it was created.
3. When `sayHello("Alice")` is later invoked:
   - It needs `greeting`.
   - It finds `greeting` stored inside its closure backpack: `"Hello"`.
   - Result: `"Hello, Alice!"`.

8. REAL-WORLD USE CASES OF CLOSURES
================================================================================

--------------------------------------------------
USE CASE 1: DATA PRIVACY & ENCAPSULATION
--------------------------------------------------
In JavaScript, variables inside objects are usually public. Closures allow you to 
create private variables that cannot be modified directly from the outside, 
similar to private fields in OOP.

Example: A Bank Account / Counter
--------------------------------------------------
function createBankAccount(initialBalance) {
    let balance = initialBalance; // PRIVATE variable! No one can do account.balance = 1000000

    return {
        deposit: function(amount) {
            if (amount > 0) {
                balance += amount;
                console.log(`Deposited $${amount}. New balance: $${balance}`);
            }
        },
        withdraw: function(amount) {
            if (amount > 0 && amount <= balance) {
                balance -= amount;
                console.log(`Withdrew $${amount}. Remaining balance: $${balance}`);
            } else {
                console.log("Insufficient funds or invalid amount!");
            }
        },
        getBalance: function() {
            return balance;
        }
    };
}

const myAccount = createBankAccount(100);

myAccount.deposit(50);         // Deposited $50. New balance: $150
myAccount.withdraw(30);        // Withdrew $30. Remaining balance: $120
console.log(myAccount.getBalance()); // 120

// Trying to access or change the private variable directly:
console.log(myAccount.balance); // undefined! (Protected!)
myAccount.balance = 9999999;    // Creates a dummy property, does NOT touch real balance!
console.log(myAccount.getBalance()); // Still 120! Safe!
--------------------------------------------------


--------------------------------------------------
USE CASE 2: FUNCTION FACTORIES
--------------------------------------------------
You can use closures to build functions that generate customized functions.

Example: Math Multipliers
--------------------------------------------------
function makeMultiplier(multiplier) {
    return function(number) {
        return number * multiplier;
    };
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);
const tenX   = makeMultiplier(10);

console.log(double(5)); // 10
console.log(triple(5)); // 15
console.log(tenX(5));   // 50
--------------------------------------------------


--------------------------------------------------
USE CASE 3: FUNCTION CURRYING
--------------------------------------------------
Currying is a technique where a function with multiple arguments is transformed 
into a sequence of functions, each taking a single argument.

Example:
--------------------------------------------------
function multiply(a) {
    return function(b) {
        return function(c) {
            return a * b * c;
        };
    };
}

console.log(multiply(2)(3)(4)); // Output: 24
--------------------------------------------------


--------------------------------------------------
USE CASE 4: EVENT LISTENERS & TIMERS
--------------------------------------------------
Closures allow event handlers and asynchronous callbacks to retain context.

Example: Button Click Tracker
--------------------------------------------------
function setupButton(buttonId) {
    let clickCount = 0; // Private state for this specific button

    document.getElementById(buttonId).addEventListener("click", function() {
        clickCount++;
        console.log(`Button clicked ${clickCount} times`);
    });
}
// Each button gets its own isolated click counter through closure!
--------------------------------------------------


--------------------------------------------------
USE CASE 5: MEMOIZATION (CACHING EXPENSIVE COMPUTATIONS)
--------------------------------------------------
Closures can store a private cache object so repeated function calls with the 
same inputs return instantly without recalculating.

Example:
--------------------------------------------------
function memoizedSquare() {
    const cache = {}; // Private cache retained via closure

    return function(n) {
        if (n in cache) {
            console.log(`Fetching ${n} from cache...`);
            return cache[n];
        } else {
            console.log(`Calculating result for ${n}...`);
            const result = n * n;
            cache[n] = result;
            return result;
        }
    };
}

const square = memoizedSquare();
console.log(square(5)); // Calculating result for 5... -> 25
console.log(square(5)); // Fetching 5 from cache... -> 25 (Instant!)
console.log(square(6)); // Calculating result for 6... -> 36
--------------------------------------------------

9. CLASSIC INTERVIEW QUESTIONS & GOTCHAS
================================================================================

QUESTION 1: The Infamous `var` with `setTimeout` in a Loop
--------------------------------------------------
What does this code print?
--------------------------------------------------
for (var i = 1; i <= 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}

Surprise Output after 1 second:
4
4
4

WHY DOES THIS HAPPEN?
1. `var` is function-scoped (or global here), NOT block-scoped. There is only ONE shared `i` variable in memory.
2. The `for` loop finishes running almost instantly, and `i` increments to 4.
3. 1000ms later, the 3 `setTimeout` callbacks run.
4. When they look for `i` in the scope chain, all 3 find the SAME shared `i`, which is now 4!

HOW TO FIX IT:

Fix Option 1 (Modern & Best): Use `let` instead of `var`
Because `let` is block-scoped, a new binding for `i` is created for EVERY iteration of the loop!
--------------------------------------------------
for (let i = 1; i <= 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// Output after 1 sec: 1, 2, 3 (Correct!)
--------------------------------------------------

Fix Option 2 (Classic): Use an IIFE (Immediately Invoked Function Expression)
Creates a new function scope on every iteration to lock in the current value:
--------------------------------------------------
for (var i = 1; i <= 3; i++) {
    (function(currentI) {
        setTimeout(function() {
            console.log(currentI);
        }, 1000);
    })(i);
}
// Output: 1, 2, 3
--------------------------------------------------

Fix Option 3: Pass argument directly into `setTimeout`
--------------------------------------------------
for (var i = 1; i <= 3; i++) {
    setTimeout(function(val) {
        console.log(val);
    }, 1000, i);
}
// Output: 1, 2, 3
--------------------------------------------------


QUESTION 2: Do Closures Cause Memory Leaks?
--------------------------------------------------
- Not inherently, but if used carelessly, YES.
- Because a closure retains references to outer variables, those variables 
  CANNOT be garbage-collected as long as the inner function is still reachable.
- If you attach closures holding large objects or DOM nodes to global event listeners 
  and never remove them, memory will not be freed.

Solution:
- Clear event listeners when components unmount.
- Set unused variables or functions to `null` when no longer needed.

10. QUICK REVISION CHEAT SHEET
================================================================================

1. SCOPE:
   - Defines where variables live and where they can be accessed.
   - Global: Anywhere.
   - Function: Inside that function only.
   - Block: Inside `{ ... }` for `let` and `const`.

2. LEXICAL SCOPE:
   - Scope is resolved based on WHERE code is written, not where it is called.
   - Inner functions can see outer variables; outer functions cannot see inner variables.

3. SCOPE CHAIN:
   - The hierarchy of scopes searched from innermost outwards to global scope.

4. CLOSURE:
   - An inner function that remembers and retains access to its parent function's 
     variables even after the parent function has finished executing.

5. WHY USE CLOSURES?
   - Data hiding / private variables.
   - Preserving state across function calls (counters, factories).
   - Currying and Partial Application.
   - Event handlers, callbacks, and memoization.

6. GOLDEN INTERVIEW TIP:
   - "A closure is created every time a function is created, at function creation time."
   - Closures give functions access to their outer lexical environment!
